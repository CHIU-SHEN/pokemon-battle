## 5. 正式训练样本的最低 schema

每条逐步样本必须包含：

| 字段组 | 必填内容 | 缺失时怎么处理 |
| --- | --- | --- |
| 身份 | schema、game_id、decision_id、player、turn、ruleset | 不进正式集 |
| 输入 | 行动者可见状态、截至当前的公开事件 | 不可补未来信息 |
| 动作 | 全部合法动作、稳定动作 ID、实际动作 | 无合法动作集合时不训练 policy |
| 老师 | V0 动作；V1 候选分数/访问量/排名 | 没跑老师就置空 |
| 结果 | 最终胜负、value、risk | 只训练实际存在的目标 |
| 卡组 | 双方 deck_id、特征、相似度 | 未知就置空，不猜测 |
| 来源 | source、quality、weight、生成器版本 | 无来源不进入正式集 |

同一 `game_id` 必须整体进入 train、valid 或 test 中的一个集合，禁止按决策随机切分。

### 5.1 短序列训练视图的附加 schema

`training_decision_v1` 继续作为不可变的单步事实层；序列训练通过派生 manifest 或索引引用它，不复制并改写原始监督字段。每个序列窗口至少需要：

| 字段组 | 必填内容 | 约束 |
| --- | --- | --- |
| 顺序 | sequence_id、game_id、player、position、valid_length | 顺序必须由显式字段生成，不能依赖 JSONL 物理行序 |
| 边界 | turn boundary、episode reset、padding mask | 每局和每个玩家视角正确清空隐藏状态 |
| 历史 | 当前公开局面、上一己方动作、相邻己方观察间的公开状态差分 | 不含未来事件与对手隐藏 option；日志为空时仍可由差分工作 |
| Combo | 前置条件、里程碑、终止原因、未来 N 步可见结果 | 只标注规则可验证事件，不把录像动作默认视为最优 |
| 监督 | 每个时间步自己的合法 options、动作与现有 policy/value 标签 | 每步动态 mask 独立计算 |

窗口构造完成后必须报告：可排序对局比例、有效窗口数、长度分布、跨回合比例、缺失事件比例、泄漏审计结果和各 Combo 类型覆盖率。
