# 服务器共享模型训练指南

本指南对应第一阶段 `SL-0-shared` 单步决策基线。该阶段已完成 6 epoch 全量训练、产物回收和冻结 test 评估；完整产物以 `artifacts/sl0_shared_full/` 为准。`SL-0` 不是最终共享模型；后续还要构造短决策序列并训练 `SL-1-seq`，显式学习跨多步 Combo。

## 0. 发给外部训练人员的文件

优先发送 `release_assets/pokemon-tcg-sl0-trainer-handoff-v2.tar.gz`。它已经把正式训练数据、manifest、训练代码、依赖、测试、本指南和交付要求放在同一个自包含包中。

共享模型训练不需要额外发送原始 Kaggle replay、`kaggle_decisions.jsonl`、失败对局中间 JSONL、V1 candidates/labels 或旧 `.part`；这些内容已经合并进正式训练集，重复发送只会增加体积。

上传 `release_assets/pokemon-tcg-training-data-v2.tar.gz`，在仓库根目录解压：

tar -xzf pokemon-tcg-training-data-v2.tar.gz

校验恢复后的正式训练集：

## 2. 环境准备

建议 Python 3.11。先根据服务器 CUDA 驱动，从 PyTorch 官方安装页选择匹配的 PyTorch wheel，再安装其余依赖。不要盲目安装不匹配的 CUDA wheel。

```bash
python -m pip install numpy
# 然后安装与服务器 CUDA 匹配的 torch
```

确认环境：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
python tests/test_shared_training.py
```

测试应输出：

```text
OK: SL-0-shared streaming, mask, loss, backward and reload
```

## 3. 第一次小样本冒烟

先使用单进程、精确样本上限，避免把 DataLoader worker 的分片上限误认为全局上限：

```bash
python -m src.train.train_shared \
  --device cuda \
  --epochs 3 \
  --batch-size 64 \
  --num-workers 0 \
  --max-train-samples 10000 \
  --max-valid-samples 2000 \
  --shuffle-buffer 2048 \
  --output artifacts/sl0_shared_smoke
```

冒烟验收：

- 无 CUDA OOM、NaN 或非法 mask；
- `metrics.jsonl` 中训练 loss 有下降趋势；
- `best.pt` 和 `last.pt` 均生成；
- 使用 `--resume artifacts/sl0_shared_smoke/last.pt` 可以继续运行；
- `run_config.json` 中数据集 SHA-256 与 manifest 一致；
- 记录 samples/s、epoch 时间、峰值显存和 GPU 利用率。

## 4. 单 GPU 完整训练模板

冒烟通过并确定 batch size 后再运行：

```bash
python -m src.train.train_shared \
  --device cuda \
  --epochs 6 \
  --batch-size 256 \
  --num-workers 4 \
  --shuffle-buffer 8192 \
  --learning-rate 3e-4 \
  --output artifacts/sl0_shared_full
```

如果显存不足，依次降低 `--batch-size`，并用 `--grad-accum` 保持有效 batch。若 GPU 利用率低而 CPU/磁盘繁忙，先调整 `--num-workers`，不要直接加模型规模。

## 5. 多 GPU 模板

代码支持 `torchrun`/DDP，每个 rank 和 DataLoader worker 会按 `sample_id` 稳定分片：

```bash
torchrun --standalone --nproc_per_node=2 -m src.train.train_shared \
  --epochs 6 \
  --batch-size 256 \
  --num-workers 4 \
  --shuffle-buffer 8192 \
  --output artifacts/sl0_shared_full_ddp
```

`--batch-size` 是每个 GPU 的 batch size；有效总 batch 约为 `batch-size × GPU 数 × grad-accum`。多 GPU 前先完成单 GPU 冒烟。

## 6. 断点续训

```bash
python -m src.train.train_shared \
  --device cuda \
  --epochs 8 \
  --resume artifacts/sl0_shared_full/last.pt \
  --output artifacts/sl0_shared_full
```

checkpoint 会校验训练集 SHA-256；数据集不一致时拒绝静默续训。

## 7. 输出文件

| 文件 | 用途 |
| --- | --- |
| `run_config.json` | 模型、训练参数、设备和数据哈希 |
| `metrics.jsonl` | 每个 epoch 的训练与验证指标 |
| `best.pt` | 验证 loss 最优 checkpoint |
| `last.pt` | 最近 epoch checkpoint，可断点续训 |

`SL-0-shared` 完成后先冻结 checkpoint 和报告，并将其作为序列模型初始化与消融基线，不要立刻启动 Top10 Adapter 或循环赛。

## 7.1 冻结测试集评估

即使只拿到 `best.pt`，也可以完成测试集评估；`last.pt` 只是断点续训所需。在仓库根目录运行：

本机 RTX 50 系显卡使用 CUDA 12.8 评估依赖：

```powershell
conda activate pokemon-tcg
python -m pip install -r requirements-eval.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

然后运行：

```bash
python -m src.train.eval_shared \
  --checkpoint artifacts/sl0_shared_full/best.pt \
  --split test \
  --device cuda \
  --batch-size 256 \
  --output reports/sl0_shared_test.json
```

评估会校验 checkpoint schema 及其内嵌的数据集 SHA-256，并报告总体指标、剔除强制单选后的指标、各监督来源指标、非法 top-1 计数和推理吞吐。如需对 5 GiB JSONL 本体重新计算哈希，额外传入 `--verify-data-sha256`。

当前冻结结果：最佳 checkpoint 为 epoch 1，valid loss 2.1546；87,992 条 test 样本上 loss 2.1134、policy top-1 60.27%、剔除强制单选后 57.72%、value MSE 0.8916、非法 top-1 为 0。完整结果见 `reports/sl0_shared_test.json`。

## 8. `SL-0` 完成后的固定训练顺序

1. 按 `game_id` 核对每局决策是否可由 `turn/decision_index` 稳定排序，并审计同一玩家视角、跨回合边界和隐藏信息可见性。
2. 从完整轨迹生成 8、16、32 步短窗口及 padding/reset mask；训练/验证/测试继续沿用原 `game_id` 切分。
3. 先训练不带循环网络的 `SL-0-history`，验证最近动作、回合内已用资源和 Combo 前置条件是否有增益。
4. 以 `SL-0` checkpoint 初始化单层小型 GRU 版本 `SL-1-gru`，每步仍只对当时合法 options 计算 loss。
5. 比较 `SL-0`、`SL-0-history` 和 `SL-1-gru` 的离线指标、Combo 指标、推理 p95 与固定 Arena；大型 Transformer 不作为默认实验。
6. 只有序列版在合法性不退化的前提下稳定提高 Combo 完成率或整局胜率，才冻结它作为 Top10 Adapter 的共享主干；否则保留 `SL-0`。

序列索引、Combo 标签器和 `SL-0-history` 已实现并完成本机冒烟。下一步服务器任务及晋级门槛见 [服务器 SL-0-history 与 GRU 训练指南](服务器SL0-history与GRU训练指南.md)。GRU 仍需等待 history 全量 A/B 结果；不要自行把相邻 JSONL 行直接拼成序列，也不要假定文件物理顺序就是对局顺序。
