# MCTS 混合策略决策

更新日期：2026-08-05

## 决策

MCTS 蒸馏后续不再只追求“完全移除搜索的纯学生”。正式路线改为同时保留两种部署形态：

1. 纯 policy/value 学生，用于最低延迟和严格时间预算。
2. policy/value 学生引导的小型在线 MCTS，用 8 或 16 次 simulations 修正关键决策。

128 simulations 的强 MCTS 继续承担教师、数据标注和能力上界角色，不作为唯一部署方案。

## 依据

Kaggle 的 `Reinforcement Learning and MCTS sample code` 采用 AlphaZero 风格循环：当前
policy/value 网络提供先验概率和叶节点价值，MCTS 通过 Search API 扩展状态，自我对战产生
新的 value/policy 标签，再更新同一个网络。它没有固定教师与独立学生的离线蒸馏阶段；评估时
仍然调用 MCTS，因此最终智能体是“网络 + 在线搜索”，而不是纯网络。

这可以视为迭代式在线搜索蒸馏。其训练和推理分布一致，避免纯学生在一次错误后进入未见状态时
完全失去搜索纠错能力。

## 与当前项目的结合

当前 v2 纯学生在 400 局中取得 182 胜、216 负、2 平，有效胜率 45.73%，安全指标为零。
这说明部署和安全性合格，但 128 次搜索产生的能力没有被纯策略稳定继承。下一阶段不再把
“纯学生超过 53%”视作唯一成功条件。

v3 流水线保持以下职责：

- 先用 400 局验证 128 simulations / depth 10 教师是否达到 58%。
- 教师通过后采集 5,000 局高质量 visit/value 数据。
- 训练可同时服务纯策略和小型在线 MCTS 的 policy/value 网络。
- 保留严格的异常、非法动作和安全回退门控。

## v3 结果返回后的固定评估矩阵

使用相同基线、相同 swapped-seat 种子和相同局数评估：

| 候选 | simulations | 目的 |
| --- | ---: | --- |
| 纯学生 | 0 | 最低延迟基线 |
| 混合学生 S8 | 8 | 首选低成本搜索方案 |
| 混合学生 S16 | 16 | 更强的搜索修正方案 |
| 强教师 S128 | 128 | 能力上界和数据质量验证 |

每个候选先跑 100 局筛选，再对保留候选跑 400 局正式门控。必须记录：

- 胜、负、平和 Wilson 95% 区间
- 平均与 P95 决策耗时
- exceptions、illegal actions、fallback rate
- 双方座位结果
- 搜索实际完成次数与超时比例

## 晋级原则

- 安全硬门：`exceptions=0`、`illegal_actions=0`、`fallback_rate=0`。
- 强度目标：400 局有效胜率至少 53%。
- 优先选择满足强度目标且 P95 延迟最低的候选。
- 如果 S8 已达到目标，不因 S16 胜率小幅提高而自动选择 S16；必须同时考虑时间预算。
- 强教师即使最强，也只有在比赛时间预算允许时才可作为部署候选。
- 任何候选都不自动晋级，最终替换仍需显式决定。

## 后续迭代

第一轮混合评估完成后，再引入多对手/DAgger 数据：使用当前学生实际对战访问到的状态，让
128 次教师重新标注，并混合当前基线、历史强策略、学生自博弈和随机化对手。该步骤不得在
教师 400 局强度门控之前扩大运行成本。
