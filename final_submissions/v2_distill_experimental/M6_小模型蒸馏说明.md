## 已交付文件

- `src/train/distill_schema.py`：固定 distillation JSONL schema、样本合法性检查、按 `game_id` 切分 train/valid。
- `src/train/features.py`：只使用比赛可见 observation 的轻量特征，包含回合状态、区域/owner、HP/damage/energy、option 局部特征、卡牌 tag、card-id hash fallback。
- `src/train/collect_distill.py`：从 V1 search / V0 rule teacher 采集样本。
- `src/train/train_distill.py`：NumPy 线性 policy/value/risk 多任务训练，导出纯 JSON 模型。
- `src/train/reanalysis.py`：按 V0/V1 分歧、关键局面、终局/多选项、高置信错误生成 reanalysis 队列。
- `tests/test_distill_pipeline.py`：M6 端到端 smoke test。
- `jobs/m6_distill.slurm`：服务器 CPU 作业脚本。

## 数据 schema 要点

每条样本包含：

- `features`：局面级可见特征；
- `options` / `option_features`：每个候选 option 的局部特征；
- `legal_mask`：option 合法 mask；
- `v0_action`：规则策略动作；
- `search_action`：V1 search teacher 动作；
- `final_action`：最终蒸馏目标；
- `search.visits` / `search.q_values`：搜索访问与 Q 值摘要；
- `game_result`：如本地对局已结束则记录，否则为 `null`；
- `budget`：teacher 搜索预算；
- `is_key`：是否关键局面。

推理特征只来自可见 observation；Search API/隐藏状态只允许作为 teacher，不写入模型输入。


也可以显式指定项目路径：


当前 Slurm 输出使用服务器模板里的 `#SBATCH -D /share/home/shenhanxi`、`#SBATCH -o job.%j.out`、`#SBATCH -e job.%j.err`，所以日志会出现在 `/share/home/shenhanxi/job.<JOBID>.out` 和 `/share/home/shenhanxi/job.<JOBID>.err`。

如需 GPU 版训练，可在 Slurm 中增加：

```bash
#SBATCH --gres=gpu:1
```

但当前 NumPy 线性蒸馏不会使用 GPU。

## 晋级标准

V2 只有在以下条件满足后才可进入 `submission`：

- 已有按 game 切分的高质量搜索样本，规模达到至少数十万；
- policy top-k 与 value/risk 离线指标稳定；
- 同等时间预算实战强于 V1，或胜率相近但显著更快；
- 不引入依赖、序列化、推理崩溃风险。

当前阶段未满足这些条件，所以主提交继续保持纯规则 safe V0；Search V1、elite deck 与 V2 蒸馏都只作为实验资产保留。
